# 場所の保存と写真

## 使い方

1. 足跡画面の「この場所に写真を残す」、または写真一覧の「現在地に新しい場所を追加」を押します。
2. 「現在地を取得」で位置情報を許可し、場所の名前と任意のメモを入力します。
3. 「場所を保存して写真へ」で `POST /pins` に保存します。
4. 「写真を撮る」または「写真ライブラリから選ぶ」で写真を用意します。
5. プレビューの「この場所に保存する」を押すと、保存済み写真として表示されます。
6. 「閉じる」で元の画面に戻れます。保存した場所と写真は写真一覧から開き直せます。

足跡画面からの撮影はモーダルで表示し、散歩の記録処理をアンマウントしません。
アプリが前面にある間は座標取得・定期保存を継続します。OSのカメラ画面やバックグラウンド中のGPS取得は保証しません。
場所の保存だけ先に完了し、撮影をキャンセルした場合は写真0枚の場所が残ります。
現在地を取得できない場合でも、既存の場所からは写真を追加できます。

現在地は取得後2分以内・誤差100m以内を確認して保存します。古い位置や精度不足は再取得を案内します。
通信失敗時は座標・場所名・メモ・リクエストIDを固定して再送し、同じ場所の重複作成を防ぎます。

## 認証と未保存データ

ログイン・足跡・写真は `AuthSessionProvider` の認証状態を共有します。
新規作成モーダル内の401は、散歩の記録・場所の保存リクエスト・選択済み写真を保持したまま、
同じアカウントで再ログインできます。保存は再ログイン後に再試行してください。
写真の処理中・未保存プレビューがある間はモーダルを閉じられません。先に保存またはキャンセルしてください。
通常の写真一覧・個別写真ルートは従来どおり、401でログインを要求します。
トークンと未送信データはメモリ保持のため、アプリ強制終了・リロード後には復元しません。

## 構成

- `CreatePinForm.tsx` / `location.ts` / `pinDraft.ts`: 現在地取得、入力確認、再試行可能なピン作成。
- `NewPlacePhotoModal.tsx`: 足跡を維持したまま作成・撮影する画面と再認証。
- `PhotoHubScreen.tsx`: 保存した場所の一覧と新規作成の入口。
- `PinPhotosScreen.tsx`: ルート画面と、モーダルでも再利用する `Gallery`。
- `session.tsx`: 既存認証との共有と、モーダル内での認証切れの処理。

## 設定と動作

- `EXPO_PUBLIC_API_URL` をAPIのURLに設定します。実機ではPCのLAN内IPを使います。
- Expo ImagePickerで撮影/選択し、ImageManipulatorで長辺1600px以内のJPEGに変換します。24MPを超える元画像は拒否します。HEICなどは端末側でデコードできる場合のみ変換できます。
- プレビューを確認してから保存します。画像加工・保存処理中は操作を抑止します。
- 1回の選択に1つの `client_request_id` を発行し、失敗時の再試行では同じ変換済みファイルとIDを使います。画面を閉じると未送信データは復元しません。
- 写真はBearer付きfetchで取得し、一時的なdata URIで表示します。公開URLや署名トークン入りURLは作りません。
- 拡大表示と削除確認あり。端末の元画像は削除しません。
- 写真の一時変換ファイルはExpoのキャッシュ領域に保存されます。端末OSのキャッシュ管理に従います。
- Webのカメラ操作はブラウザー・端末依存です。PCではファイル選択になる場合があります。選択のキャンセルが通知されないブラウザーでは「写真の選択をやめる」で戻れます。実機で撮影/許可拒否/再許可を確認してください。
- iOS/Androidの権限文言を反映するにはアプリの再ビルドが必要です。マイク権限は要求しません。

## API契約

詳細は `backend/PHOTOS.md` を参照してください。送信形式は `multipart/form-data`、フィールドは `file` と `client_request_id`。Content-TypeのboundaryはFormDataに任せます。

実機確認項目: カメラ許可/拒否、写真選択キャンセル、縦横写真の向き、撮影→プレビュー→保存、通信切断後の再送、5枚上限、期限切れ認証、一覧・拡大・削除、地図からのpinId受け渡し。
